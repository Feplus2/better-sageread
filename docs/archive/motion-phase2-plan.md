# 动效体系二期立项：共享元素转场 + 手势驱动（motion phase-2）

> 2026-08-25 立项草案（待用户拍板后开工）。一期批次 1/2 见 `docs/archive/motion-system-plan.md` 第七节
> （地基三档 + 小 DOM + tab 转场 + 侧栏）。本文档只管二期两个候选：framer-motion 登场的两个场合。
>
> **2026-08-28 用户裁定：整体悬置**——候选 A 讨论中「封面飞首屏」被否（封面不在阅读器
> 首屏、影响范围有限），曾重定向为「卡片即容器」Morph 式转场（容器变形 + 标题共享元素），
> 终裁风险与收益不成正比，悬置。重启需重新拍板，本文档留档。

## 1. 前置条件（开工门禁）

- 一期批次 1–4 全部落地并实测（尤其：tab 交叉淡入、侧栏覆盖/冻结式、性能三档全量回归）。
- 一期暴露的遗留问题清零（残影、快速连打、大 DOM 压力场帧率）。
- 性能模式三档已稳定运行——二期的 JS 动画必须同样接 `data-motion` 退化链
  （fade-only 下 layout 动画退化为 fade；reduced 下 0.01ms）。

## 2. 候选 A：共享元素转场（封面 → 阅读器）

**场景**：图书馆/文献库卡片封面 → 阅读器打开，封面图连续放大过渡到阅读器首屏位置
（iOS「打开 App」同款）。这是"同一物体连续移动"原则里最出彩的一件。

**实现选型**：framer-motion `layoutId`（裁定五已否决 View Transitions API：
macOS WKWebView / Linux WebKitGTK 不支持）。封面图挂 `layoutId="cover-{bookId}"`，
阅读器首屏同 id 接收；保活 tab 架构下两层同帧在场，layout 动画天然可行。

**工程量评估**：中。要点：
- 阅读器打开路径的封面渲染点（首屏封面区/缺省封面占位）须与卡片封面像素级同源
  （同一图片资源、同一 aspect-ratio 容器），否则 layout 动画起止帧跳变。
- 论文 tab 无封面概念——只限图书；无封面图的书（占位色块）退化为 fade。
- 与 tab 休眠机制（reader-layout.tsx:88-154）的交互：动画期间目标 tab 必须已挂载
  （休眠唤醒路径要抢在动画开始前完成首帧）。
- 性能：layout 动画在 framer-motion 里走 transform 缩放（不触 layout 重排），
  符合第一宪法；但 layoutId 测量有 getBoundingClientRect 成本，大 DOM 页实测验收。

**验收**：书库→阅读器打开/关闭双向连续；快速连开两本书不串动画；
fade-only 档退化为交叉淡入；论文页打开不受影响。

## 3. 候选 B：手势驱动 + 可中断（侧栏边缘拖拽）

**场景**：阅读器/书库侧栏支持从边缘拖拽开合，跟手、按速度决定开合（甩出去/弹回去），
动画任意时刻可中断反向（从当前位置接着来，不回零）。

**实现选型**：framer-motion 手势（drag）+ `animate` 弹簧（spring）。CSS transition
干不了手势（裁定一）。与裁定三的覆盖式侧栏天然兼容（拖拽的是覆盖层 transform）。

**工程量评估**：高。要点：
- 拖拽阈值/速度判定（iOS 口径：过半或速度足够即开合）；拖拽期间实时 transform，
  松手后 spring 收尾。
- 与 re-resizable 宽度拖拽的冲突域划分（边缘 8-12px 热区归手势开合，宽度拖拽柄归
  re-resizable——两者热区不得重叠，一期侧栏批次须预留此边界）。
- 阅读器 iframe 内容区对手势的pointer事件拦截问题（EPUB iframe 吞事件——覆盖式
  侧栏在内容之上，拖拽手柄需在 iframe 外层）。
- 可中断重定向：spring 动画从当前速度接续（framer-motion 原生支持），
  快速来回开合实测不弹跳不卡死。

**验收**：跟手性主观验收（用户手感签字）；中断反向无跳帧；键盘/按钮开合路径不回归。

## 4. 明确不做（二期边界）

- vaul/drawer 库（桌面端无场景，一期已排除）。
- 划线/标注高亮动效（裁定四，closed shadow DOM 物理不可达）。
- 页面级 3D 翻转/视差等装饰性动效（与本应用的阅读工具定位不符）。
- 全局动画编排框架化（framer-motion 仅限上述两个点，不做全局接管）。

## 5. 风险

1. **framer-motion 在主线程**：论文页大 DOM 负载下 JS 动画自身就是掉帧源
   （motion-plan 裁定一已述）——二期两项全部要在大 DOM 压力场实测帧率，
   不合格就缩回 fade 退化，不硬上。
2. **layoutId 与保活架构的细节交互**（休眠/唤醒/zIndex）是最大不确定点，
   候选 A 先做 spike 验证（一本书的最小闭环），验证不过则候选 A 整体缓行。
3. 手势与既有拖拽/划词热区冲突是细节雷区，实施前先把热区地图画出来再过目。
