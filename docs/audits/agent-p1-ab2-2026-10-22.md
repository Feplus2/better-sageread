## 4. 归因（为什么步数少了、token 反而高）

1. **每步 prompt 变大**：new 模式退出目录牌后，17 个工具的完整 schema（约 9.8k 字符 ≈ 2.4k token）随每次请求发送；legacy 用目录牌只发一句目录（约 1–2k 字符）。new 平均少 0.34 步，但每步多几千 token，净亏。
2. **readDocument 过度扩读**：new 模式 readDocument 被调用 72 次（全部工具调用 127 次的大头）；未索引书 3 次都是 `getDocumentInfo + 6×readDocument` 固定套路，39k → 128k。预算 32k 只限制了字符，但没有限制「调用次数/回答时机」。
3. **跨文献仍是读多于找**：new 轨迹是 getBooks → getDocumentInfo → 多窗 readDocument；legacy 靠 readPaperFull 一次灌全文，步数反而少（token 也不低）。

## 5. 结论与下一步（P1-4）

- 默认 `documentToolMode` 保持 `both`（不切 new）；旧工具继续保留 alias。
- P1-4 目标：把 new 模式 token 压到 legacy 以下，再重新 A/B：
  1. **恢复轻量目录牌**：new 模式保留 17 个工具，但强制目录牌（只发名字+一句话）；真实操作经 useTool。预计每步省 ~2.4k token，describeTool 会回升但总量下降，需实测。
  2. **readDocument 调用预算**：同一轮最多 3 次；第 4 次起返回「预算已尽，请作答」。未索引书固定 7 步的套路直接砍掉一半。
  3. 书籍目录注入再压到 20 条（当前 35），并给 getDocumentInfo 附「只读目标小节」提示。
  4. 跨文献模板化：searchLibrary 命中 → readDocument 每篇最多 2 窗；G1 的 readPaperFull 式全文灌入不再默认允许。
